# Matrix structured observations: exact evidence without PDFs

Research for [VNIBB issue #36](https://github.com/Kohnnn/vnibb/issues/36), inspected at [repository commit 20fa4c392e22a42b2d150de22989bb2331a98adb](https://github.com/Kohnnn/vnibb/tree/20fa4c392e22a42b2d150de22989bb2331a98adb), 2026-09-26. **Research finding, not a Matrix product decision.** Source and official documentation only: no live corpus/provider calls, PDFs, issuer filing, tests or app change. Linked source code is pinned to the inspected revision. Schema fields indicate possible locators, not proof of a production row.

## Answer and boundary

**Best bounded candidate:** a stored daily OHLCV **close observation** in Mongo `market_prices_eod` has a trade-day key, value, source and VND price unit at rest; Vietcap writer makes `sourceKey=vietcap:<SYMBOL>:eod:<YYYY-MM-DD>`. An authorized resolver of a *selected stored row* could freeze the number plus these attributes to reproduce what VNIBB served, subject to verifying actual row existence, adjustments, retention and rights. The current MCP EOD history does **not** expose source/sourceKey/priceUnit: the reader strips them by default. This VNIBB-generated store locator is not an original exchange trade ID, issuer document or upstream immutable revision. [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/scripts/vietcap/backfill_vietcap.py#L104-L186) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/services/mongo_market_data_service.py#L65-L112) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/services/mongo_market_data_service.py#L397-L560) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/mcp/server.py#L1235-L1280)

A bounded statement metric (e.g. income-statement revenue for a symbol and fiscal period) remains suitable for comparison as *structured analysis*, but the standard HTTP, AI and MCP summaries **cannot support an honest exact original-source citation**: values can blend provider sources and serving stores, and neither metric nor period identifies a filed statement line, unit, consolidation/audit basis or historical vintage. A separate stored Vietcap raw period row plus its code-to-label metric map is a **conditional feasibility path** for an exact structured *stored observation*, if the field code, numeric value, period, unit and a frozen version are verified. Do not present it as an issuer filing. [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/providers/vnstock/financials.py#L373-L480) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/providers/vnstock/financials.py#L100-L183) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/api/v1/equity.py#L5236-L5325) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/scripts/vietcap/vietcap_writers.py#L36-L160)

**VCI reference contract (code, not legal permission):** The VNIBB Vietcap client names `GET /v1/company/<symbol>/financial-statement/metrics` (section code/labels), `GET /v1/company/<symbol>/financial-statement?section=...` (years/quarters) and `GET /v1/company/<symbol>/statistics-financial` (ratios). Writer maps `yearReport` and `lengthReport` 1–4 to `<year>-Q<n>`, otherwise `FY<year>` (comment identifies annual as 5), stores `raw` and a period key; label map keyed on `(comTypeCode,section,source)` and `field`. A field-to-number join, whether unit/issuer basis are present in a specific raw row and how a category map changes must be checked; `comTypeCode` is not audit status or an issuer ID. Ratios `finance.ratio` have separate period/ratioType keys, not price/denominator proof. ## Official documentation claims and rights, not code guarantees

- [Vnstock official Community fundamental manual](https://vnstocks.com/docs/vnstock/phan-tich-co-ban-fundamental) documents year/quarter, report/time-series orientations, `item`/`item_en`/`unit` in report output and period columns, with bounded period count. [Official Market manual](https://vnstocks.com/docs/vnstock/du-lieu-thi-truong-market-data) documents OHLCV; [Community introduction](https://vnstocks.com/docs/vnstock/gioi-thieu-vnstock) describes guest/key limits. These are package docs, **not a VNIBB unit guarantee**. Repository dependency pins `vnstock>=4.0.4,<4.1` and separately bootstraps Sponsor packages. [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/pyproject.toml#L29-L52)
- [Vnstock's effective software licence, license-2026.09](https://vnstocks.com/onboard/giay-phep-su-dung) grants rights to software, **not third-party source data**; source access, storage, display, distribution and commercial rights must be checked separately. It also specifies when software redistribution or a product whose core is third-party market-data access needs separate agreement. [Official Community/Extended comparison](https://vnstocks.com/docs/vnstock-data/gioi-thieu-vnstock-data) says `vnstock_data` is a separate closed Sponsor package and VCI return shapes differ by edition. Neither document grants permission to republish structured values through Matrix/MCP.
- [Vietcap's own website terms, intellectual-property and disclaimer sections](https://www.vietcap.com.vn/dieu-khoan-su-dung-chinh-sach-bao-mat) disclaim accuracy, reserve website-content rights and limit copying/distribution/publication beyond stated personal downloading/printing. Applicability to these particular IQ/gap-chart APIs, a small numeric metric, any negotiated agreement and external-client export is **unverified**: no blanket legal conclusion or inferred grant. Public unauthenticated endpoint access is not a licence. [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/scripts/vietcap/vietcap_client.py#L1-L33)

## Retention, missing provenance and honest states

- Premium-catalog manifest calls finance datasets and EOD `long-term`; this is an ingestion-intent label, **not an immutable-revision retention guarantee**. Operational [retention guidance](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/docs/data_retention_partitioning.md#L1-L31) sets `PRICE_HISTORY_YEARS` default 5, and 0 disables its cleanup. Actual row coverage, backups and applicable source permissions are **not verified** here. [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/scripts/backfill_mongo_vnstock_full_catalog.py#L35-L111)
- **Irretrievable from the current normalized serving row alone:** original issuer filing URL/publication time/revision, audited status, separate/consolidated basis, provider *per cell* after merges, original item code and defensible scale, prior overwritten value and as-served history. Raw fields *might* survive for a particular raw Mongo/Postgres row: inspect that row before any claim, but do not reconstruct absent past snapshots or presume original issuer provenance. [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/providers/vnstock/financials.py#L373-L480) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/providers/vnstock/financials.py#L100-L183) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/services/data_pipeline.py#L2806-L2860) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/scripts/vietcap/vietcap_writers.py#L95-L160) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/api/v1/equity.py#L646-L740)
- Honest states: `unavailable` = no retained observation; `unknown_provenance` = number exists but original producer/revision/basis unverified; `ambiguous_unit` = scale/currency unresolved; `derived` = formula and constituent observations known, not issuer assertion; `rights_unverified` = external display/export not justified by examined materials. Do not fill any state with made-up evidence. [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/providers/vnstock/financials.py#L100-L183) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/apps/api/vnibb/providers/vnstock/financials.py#L988-L1008) [source](https://github.com/Kohnnn/vnibb/blob/20fa4c392e22a42b2d150de22989bb2331a98adb/docs/data_retention_partitioning.md#L1-L31)

## Factual recommendation (not implementation or a product decision)

Start evidence feasibility with **one stored EOD close, symbol and explicit Market Trade Date**, retaining selected collection, source, sourceKey, VND unit, exact numeric value and a frozen observation revision/value together; mark missing upstream correction ID and rights unverified. Separately try **one bounded Vietcap structured income-statement metric code** only after actual raw row field, metric-map label, period, basis and unit can be checked; never convert a category/ticker ID into issuer/audit assurance. Current normalized HTTP/AI/MCP statement summaries are analysis inputs, **not exact primary evidence**; an exact claim and external MCP export require preserved observation snapshots and verified rights. This is a feasibility recommendation, not a chosen Matrix playbook, authorization, schema implementation or user decision.
