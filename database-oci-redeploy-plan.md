# Database and OCI backend redeployment plan

**Planning only; refs #220, #129 and #168/#171–#173.** No production requests, acquisition, database/cache writes, publication, deployment or scheduler enablement were performed for this refresh. The 6 November census recorded serving revision `3d17cfdf704f8b0ce5f88783144bbcb06c25f16f` and schema `b8f2c5d91e40`; these are dated observations, not today's state. Current topology, mounts, capacity, schema, credentials, backup custody and canary routes remain uninspected. Preserve stores, strict health, admin denial, no-send and external-client gates; never fabricate freshness. The [release runbook](docs/oracle_runbook.md#release-the-stack) requires this plan's prerequisites: there is no new code-only backend-release exception to the unresolved operational gates.

1. **Bounded read-only preflight.** After separate authorization, inspect only the confirmed OCI serving node (`cloud-01` if still serving) and existing builder/recovery node (`deploy-01` if still assigned); do not infer roles from names or provision replacements. Budget: at most three confirmed hosts, one strict-known-host SSH session per host, 5-second connection and 60-second remote-command deadline, no retries or expanded discovery on failure. Run `hostname`, `df -h`, `docker ps -a --format '{{.Names}} {{.Image}} {{.Status}}'` and `docker system df`; then inspect only confirmed service names with `docker inspect --format '{{.Name}} {{.Config.Image}} {{.Image}} {{json .Mounts}}'` and the Compose `com.docker.compose.project.config_files`/working-directory labels. Privately record routes/TLS termination, API/MCP/data/proxy identities, image architecture, effective Compose file order, mounts, producer state and free space; never dump environments, full inspect output, auth headers or rendered Compose secrets. Stop for unverified host keys, missing roles, revision drift or insufficient headroom for the fresh pair, expanded restores, candidate and independent rollback images.
2. **Data census, not recovery.** From the verified checkout/runtime and independently pinned `SERVING_REVISION`, run `timeout 120s env -u VNIBB_PREFLIGHT_API_BASE_URL PYTHONPATH=apps/api python apps/api/scripts/query_plan_preflight.py --readiness-census --expected-revision "$SERVING_REVISION" --mongo-max-time-ms 3000 --output-json "$PRIVATE_EVIDENCE/census.private.json"` with `umask 077` and a new private output path. Its SQL read-only transactions use 5-second statement/1-second lock deadlines; Mongo is bounded to 3 seconds, Redis to known-key `GETRANGE`/`TTL`, and receipt capture fails above 1,000 records. No API benchmark, provider or cache refresh is allowed; use the runbook's reviewed streamed-census procedure if the deployed image lacks the command. Capture success is not readiness and the cross-store window is non-atomic. Reconcile membership and Mongo/PostgreSQL/Redis lineage, receipts, coverage, stale/null/invalid reasons. The 6 November **237 `DELISTED`** membership rows remain unresolved: preserve existing predicates/flags until an authoritative dated manifest is accepted; neither silently exclude them nor count them as traded coverage.
3. **Authority remains a stop gate.** #168 still lacks applicable storage/public-serving authority and exchange/instrument/segment/finality/no-trade coverage; SDK entitlement is not permission. Obtain that acceptance and confirm #169/#170 admission/publication acceptance before acquisition or production mutation. #171 recovery, #172 daily ownership and #173 consumer/watch acceptance remain blocked; this plan does not close them. Keep all acquisition and scheduling stopped otherwise.
4. **Fresh paired backup and independent restore.** First review the installed producer against [the drill contract](docs/BACKUP_RESTORE_DRILL.md), its actual `BACKUP_DIR`, capacity estimates and `KEEP_SETS` (default 7). It prunes older sets after its own pair verification, **before off-source restore proof**; protect the last proven recovery pair and agree retention before invoking it, not after pruning. With separate write approval and adequate headroom, run `sudo /usr/local/sbin/vnibb-backup.sh` and `bash scripts/oracle/verify-backup.sh "$STAMP"` for the same new stamp. Host scratch `VERIFY OK` is PostgreSQL-only verification, not disaster recovery. Authenticated-transfer the entire PostgreSQL dump + Mongo archive + manifest set to an existing off-source isolated host; before the first byte, use `umask 077; install -d -m 0700 "$OFFBOX_SET"`, then confirm files are `0600`. Run `python3 scripts/oracle/restore-offbox.py --confirm-isolated "$OFFBOX_SET"`; require both size/hash matches, fresh networkless restores, data counts, zero restore failures, confirmed cleanup, exit 0 and `RECOVERY OK`. Retain the complete output, set ID, hashes, elapsed time and host/image identities; never substitute live-source counts for restored counts. Keep encrypted custody separate from its recovery identity and prove decryptability. Historical November 4 proof/custody caveats do not satisfy a fresh pair's gates.
5. **Accepted bounded recovery.** Only after steps 1–4 and separate approval, execute #171 through the existing pipeline; reconcile exact dated membership, source/session/unit lineage and receipts and prove idempotent replay. Keep null/stale states honest; no invented OHLC, dates, completion markers or history deletion. Approval of code or this document is not recovery acceptance.
6. **Pin release and independent fallback.** Record clean candidate SHA, passing CI run URL, repository/digest/platform, approved migration head, and independently verified last-good SHA/digest/schema-compatibility evidence. Do not derive the fallback solely from current health or reuse the candidate as its own fallback. Merging `main` runs CI, not publication or rollout. After separate publication approval, dispatch `gh workflow run publish-release-image.yml --repo Kohnnn/vnibb --ref main -f revision="$CANDIDATE_SHA" -f tag="$RELEASE_TAG"`: inputs are a full lowercase 40-hex SHA already in `main` and an unused immutable tag; the workflow publishes ARM64. Retain its run URL and `release-image-$RELEASE_TAG` artifact's `release-manifest.json`. Alternatively, from that clean SHA on an authorized non-production builder: `IMAGE_RELEASE_REVISION="$CANDIDATE_SHA" PLATFORM=linux/arm64 bash scripts/oracle/build_release_image.sh "$IMAGE_REPOSITORY:$RELEASE_TAG"`. This **pushes**, not preflights; record its emitted repository/digest/revision/platform. Pin `VNIBB_API_IMAGE_REPOSITORY` + `VNIBB_API_IMAGE_DIGEST` privately; retain current rotated credentials, never a historical environment wholesale.
7. **Rehearse exact migration.** On an approved isolated target restored from the same fresh pair, use its verified full Compose/env/mount configuration for `"${compose[@]}" run --rm --no-deps migrate -c /app/alembic.ini heads`, `"${compose[@]}" run --rm --no-deps migrate`, then `"${compose[@]}" run --rm --no-deps migrate -c /app/alembic.ini current`. Record the approved head and pre/post counts/invariants; prove the independent last-good image reads the migrated schema. `restore-offbox.py` removes its stores before success, so the drill alone is not a retained rehearsal environment. Failure or incompatible rollback blocks release; image rollback does not undo schema. No automatic downgrade, production restore or scheduler start is part of rollback.
8. **API then authenticated MCP canary.** Require an existing isolated route/target backed only by restored stores; stop if unavailable. Preserve **complete effective Compose file order and mounts**, including `--env-file deployment/env.oracle` and verified runtime overrides on every command; never blindly reuse a dated override or reintroduce premium mounts. Privately verify `API_SKIP_SCHEDULER_STARTUP=true`, `SKIP_WARMUP=true`, `SKIP_WEBSOCKET_STARTUP=true`, `PREDICTION_MARKET_POPULATE_ON_STARTUP=false`, and stopped scheduler/native producers. These flags are **not a global provider-off switch**: consumer GETs may fill caches or invoke fallback; require independently verified provider-egress isolation or stop. Require trusted TLS certificate/hostname validation (`CURL_CA_BUNDLE`/`SSL_CERT_FILE` only for an explicitly trusted private CA), never `--insecure`. Route `CANARY_URL` to the confirmed canary IP through trusted DNS; run runtime verification on that same host to bind HTTP revision to its inspected container digest. With verified Compose arguments, start **only API** using `up -d --no-build --no-deps --force-recreate api`. Run `timeout 180s env BASE_URL="$CANARY_URL" TIMEOUT=15 EXPECTED_RELEASE_REVISION="$CANDIDATE_SHA" EXPECTED_IMAGE_REPOSITORY="$IMAGE_REPOSITORY" EXPECTED_IMAGE_DIGEST="$CANDIDATE_DIGEST" bash scripts/oracle/runtime_verify.sh`, then `timeout 180s env LB_PUBLIC_IP="$CANARY_IP" HOSTNAME="$CANARY_HOST" TIMEOUT=15 bash scripts/oracle/lb_canary_validate.sh`. The latter checks `/ready`, `/live`, `/health/`, VNM profile/quote, screener and CORS with TLS `--resolve`. Recreate **only MCP** with the same Compose arguments; run `timeout 180s env BASE_URL="$CANARY_URL" EXPECTED_REVISION="$CANDIDATE_SHA" TIMEOUT=20 PYTHON_MODE=host:python3 bash scripts/oracle/mcp_smoke_test.sh` with bearer privately loaded and an installed host MCP client, avoiding the wrapper's single-Compose-file container fallback. Missing credentials/client authorization blocks acceptance; never change expected revision to fit a surprise response.

The traffic-bearing release chain (future authorization only). Set `compose=(docker compose --env-file deployment/env.oracle -f docker-compose.oracle.yml)` **only if inspection proves that is the complete serving configuration**; otherwise append each verified `-f` override in its observed order before proceeding. Define the array independently for the isolated rehearsal and traffic-bearing target; do not reuse isolated store credentials/mounts in production. No generic command can safely guess an uninspected topology.

```bash
test -n "${CANDIDATE_SHA:-}" &&
test -n "${APPROVED_HEAD:-}" &&
declare -p compose >/dev/null &&
test "$(git rev-parse --verify HEAD)" = "$CANDIDATE_SHA" &&
"${compose[@]}" config --quiet &&
"${compose[@]}" pull api mcp migrate &&
"${compose[@]}" run --rm --no-deps migrate &&
"${compose[@]}" run --rm --no-deps migrate -c /app/alembic.ini current &&
read -r -p "Confirm current equals $APPROVED_HEAD; enter release SHA: " accepted_revision &&
test "$accepted_revision" = "$CANDIDATE_SHA" &&
"${compose[@]}" up -d --no-build --no-deps --force-recreate api mcp
```

Any failed prerequisite stops this chain; migration success is not application health or schema-backward-compatibility proof. This refresh inspected source contracts and documentation only; no current host, store, route, credential, backup or runtime acceptance result is claimed.
