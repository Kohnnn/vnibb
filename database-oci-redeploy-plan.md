# Database and OCI backend redeployment plan

**Planning only:** no production execution, live host requests or provider acquisition were authorized or performed. Current OCI topology, mounts, capacity, schema and backup state are uninspected. #168 source authority and coverage remain unmet; redeployment cannot supply them. Preserve stores, strict health, admin denial, no-send and external-client gates; never replace databases, invent infrastructure or fabricate freshness.

1. **Fresh read-only census.** With separate authorization, inventory actual routes, hosts, Compose overrides, service images/mounts, capacity, schema/indexes and independently pinned serving revision. Use `hostname`, `df -h`, `docker ps -a`, `docker system df` and sanitized `docker inspect --format '{{.Name}} {{.Config.Image}} {{.Image}} {{json .Mounts}}' vnibb-db vnibb-mongo vnibb-redis` after confirming names; never expose environments. Reserve headroom for backup, restore and images.
2. **Data census.** Follow `docs/oracle_runbook.md` § Read-only database readiness census using `env -u VNIBB_PREFLIGHT_API_BASE_URL PYTHONPATH=apps/api python apps/api/scripts/query_plan_preflight.py --readiness-census --expected-revision "$SERVING_REVISION" --mongo-max-time-ms 3000 --output-json "$PRIVATE_EVIDENCE/census.private.json"`. Reconcile membership, Mongo raw records, PostgreSQL session/price/snapshot rows, receipts and Redis, including stale/invalid reasons. Capture success is not readiness; no provider, HTTP or cache refresh.
3. **Authority.** Before acquisition or production mutation, obtain separate authorization, #168 permission for storage/public serving plus exchange/instrument/segment/finality/no-trade coverage, and confirm #169/#170 admission/publication acceptance. Keep acquisition and scheduling stopped otherwise.
4. **Fresh paired backup.** With adequate space, use `sudo /usr/local/sbin/vnibb-backup.sh` then `scripts/oracle/verify-backup.sh "$STAMP"` for the same new set. Authenticated-transfer the complete pair and manifest to an isolated off-source host, creating its destination first with `umask 077; install -d -m 0700 "$OFFBOX_SET"`. Run `python3 scripts/oracle/restore-offbox.py --confirm-isolated "$OFFBOX_SET"`; retain hashes, counts, cleanup, exit status and `RECOVERY OK`. Preserve independent encrypted custody and separate key; see `docs/BACKUP_RESTORE_DRILL.md`. Host scratch verification is not off-source proof.
5. **Accepted recovery.** After these gates and separate approval, execute #171 through the existing pipeline; reconcile exact membership, source/session/unit lineage and receipts and prove idempotent rerun. Keep null/stale states honest; no fake OHLC, dates or completion markers and no history deletion.
6. **Pin candidate.** After review and CI, select a clean candidate SHA and independent last-known-good revision/digest. On an authorized non-production builder run `IMAGE_RELEASE_REVISION="$CANDIDATE_SHA" bash scripts/oracle/build_release_image.sh "$IMAGE_REPOSITORY:$RELEASE_TAG"`; record emitted repository, digest, revision and platform. Pin `VNIBB_API_IMAGE_REPOSITORY` and `VNIBB_API_IMAGE_DIGEST` privately; tags are not rollback identities and old credentials must not be restored.
7. **Rehearse migration.** On an existing isolated target restored from the fresh pair, prove candidate migration, data preservation and last-good image compatibility with the migrated schema. Record approved Alembic head and rollback decision. Failure or incompatibility blocks release; image rollback does not undo schema and automatic downgrade is forbidden.
8. **API then MCP canary.** Require an existing isolated route/target, verified mounts/stores and disabled producers; stop if unavailable. Require trusted TLS certificate and hostname verification in the canary validator. Set `CANARY_URL` to the verified TLS hostname, route it to the canary IP using trusted DNS, and run these checks on that same host so the local container digest and URL identify the same candidate. Start API only: `docker compose --env-file deployment/env.oracle -f docker-compose.oracle.yml up -d --no-build --no-deps --force-recreate api` (add verified overrides). Verify it with `BASE_URL="$CANARY_URL" EXPECTED_RELEASE_REVISION="$CANDIDATE_SHA" EXPECTED_IMAGE_REPOSITORY="$IMAGE_REPOSITORY" EXPECTED_IMAGE_DIGEST="$CANDIDATE_DIGEST" bash scripts/oracle/runtime_verify.sh`; then `LB_PUBLIC_IP="$CANARY_IP" HOSTNAME="$CANARY_HOST" bash scripts/oracle/lb_canary_validate.sh`. Recreate `mcp` with the same Compose flags, then `BASE_URL="$CANARY_URL" EXPECTED_REVISION="$CANDIDATE_SHA" bash scripts/oracle/mcp_smoke_test.sh` with its bearer privately loaded. Missing credential or client authorization blocks acceptance.
9. **Cutover / rollback.** After passing canaries and separate approval, use the fail-fast `docs/oracle_runbook.md` release chain, verified overrides and approved migration head. Monitor health/errors/latency; if it fails, restore the verified previous image/route per `docs/oracle_rollback_plan.md` but do not start its scheduler or automatically downgrade. Verify rollback identity. Never use `docker compose down -v`.
10. **Daily owner / watch.** After #168 and accepted #171, resolve #172 credential-state readability fail-closed, confirm Redis lock and exactly one producer, and separately authorize the scheduler. Observe the next completed trading session. For #173 reconcile Mongo/PostgreSQL/Redis with REST, authenticated MCP and browser counts, values, nulls and as-of dates; require the unchanged `.github/workflows/production-health-watch.yml` run to pass `/live` and `/ready` 200 and detailed `status=healthy` after recovery and the next session. Record run URL/revision; container startup does not close #129/#172.
