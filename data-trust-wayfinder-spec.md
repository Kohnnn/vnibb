# Wayfinder: production data-trust closure

Status: proposed, 2026-09-23. Active repository: `Kohnnn/vnibb` (`VNIBB/vnibb`). This map **does not reopen** the completed production-reliability map #10 or the existing rate-limit rollout #23. It closes contracts that remain false in the current source and records the recovery proof that #10 explicitly left open. Source inspection establishes the defects below; it does **not** establish their frequency in today's production traffic.

## Destination

A failed recovery drill cannot report success; operators see the separate scheduler worker's actual outcomes; market-data responses distinguish unavailable, stale, incomplete and real zero/no-match states; prediction-market reads remain bounded as the corpus grows. Prove the contracts with fault injection and a bounded production rollout rather than claiming success from green health codes alone.

## Decisions and sequencing

1. Fix A, B and C independently first. They concern recovery truth, operator truth and resource safety. A is not a substitute for H: same-host scratch restore proves only part of disaster recovery.
2. D, E, F and G may proceed independently after their response contracts are pinned; web-facing E/F/G require API and widget changes together. D uses a coverage signal grounded in the actual expected universe, not a magic minimum row count. A complete market snapshot can lag in trade date and must still report staleness separately.
3. H needs an isolated target and a runbook; it must never drop or restore over the canonical databases. I needs an explicit archival/retention policy before any destructive migration. Fix C without waiting for I.
4. For B, use durable worker-authored outcomes (the existing PostgreSQL serving store is the conservative default); do not make the API's in-memory scheduler or Redis alone authoritative. If persistence fails, report status unknown and log the write failure; do not manufacture a healthy empty result. Never expose raw exception details through a public status route.
5. Keep #23 as an external ops dependency only: shadow-mode rollout is already tracked there. No new paid service, second node, Appwrite, or premium-provider migration in this map.

## Release gates

- Targeted reproductions demonstrate each old failure before the change and its absence after it; cover each new response branch and the real restore error exit code. Test observable contracts, not source text.
- On a production-like corpus, record prediction-query plan, transferred rows, p95/p99 or repeat latency, and peak memory before and after; do not infer success from small unit fixtures.
- Deploy API/web contract changes together with backward compatibility for existing widgets. After deployment, verify worker failures appear from the API container, stale/empty/no-source surfaces are honest, and the backup drill cannot print `VERIFY OK` after a failed restore.
- Close tickets only with evidence links and observed results. Local source inspection is not a claim that production has deployed any fix.

## Local implementation evidence (2026-09-23; not a production release)

- The changed backend rejects incomplete full-Universe snapshots, reports market breadth unavailability, preserves provider/trade-date provenance, and distinguishes no-source quotes and screener outages. Focused regressions cover the complete/partial/old-trade cases and both empty and unavailable widget surfaces. Scheduler results are stored in PostgreSQL instead of process memory; prediction-market reads use SQL aggregation or bounded result sets. The archive-first retention utility is dry-run by default and requires a recent database-matched backup receipt plus operator-confirmed isolated restore before any bounded deletion.
- `env PYTHON=/tmp/vnibb-verify/bin/python node scripts/ci-gate.mjs` passed locally: frontend lint (78 nonfatal warnings), typecheck, build, Jest, changed-line backend Ruff, compile, and backend pytest. Run-specific counts and warnings belong in the gate output, not in a claim about production health.
- Built Next.js served locally at `127.0.0.1:3201`; in the actual Market Overview browser surface, an intercepted market API response with a cached heatmap, current price date and old constituent date rendered `Cached`, `Price 2026-09-23` and `Constituents 2026-09-09 (stale)`. An unavailable breadth API response rendered `Market breadth unavailable`, not an empty-match label. Other widgets reported connection failures because no backend was running at `localhost:8000`. This is visual contract proof with injected response data, **not** a live backend or production verification.
- The off-box utility rejected a missing bootstrap environment on its first final-code drill; the sudo path now preserves only `POSTGRES_PASSWORD`. A subsequent real restore of the historical `20260729T190249Z` paired set passed both SHA-256/size checks; PostgreSQL: 37 public tables, 1,742 stocks, 1,745,922 stock prices; Mongo: 7,964,485 documents, zero failures, 16 populated collections. Local verification/startup/restore/assertions measured 141.1 seconds, then both containers were removed. This proves a historical pair on this workstation, not current RPO, independent key recovery, or host-loss restoration. The 130.3-second earlier run predates the final code and is not the release proof.
- **Rollout blocked at the time of writing:** no verified current paired Postgres+Mongo backup, independent encryption-key custody/decryption on another machine, production-scale prediction query plans/latency/peak-memory observations, published digest for this revision, confirmed migration head on the serving database, or authorized OCI/Vercel release window. Several of these were satisfied on 2026-09-24 and are recorded under "Production rollout evidence" below; independent key custody, production-scale prediction-query measurements, and host-loss restore remain open. When those are observed, follow `docs/oracle_runbook.md` with the previous immutable digest and frontend rollback target preserved; verify behavior on the actual API and Vercel surfaces before closing #24 or its children.

## Production rollout evidence (2026-09-24)

- **Deployed to the Oracle stack.** Serving revision `d329dc2b2250bba00652a363684d58799939fae6`, published as `ghcr.io/kohnnn/vnibb-api@sha256:49c167d79177453c2962953022f9cf0ecb072646c48c504d13b1271f49349ed3`. `api`, `mcp`, and `scheduler` were recreated on that same pinned digest; `/health/` reports the matching `revision` field. A verified paired Postgres/Mongo backup (`20260924T175056Z`, Mongo 375 MB verified) preceded migration.
- **Migration head reached `d4c39e8a7b12`.** `20260922_1745` was found already applied in the live database (column `is_synthetic`, both indexes, 40 backfilled rows) but missing from `alembic_version`; it was stamped rather than re-run against its 14.5M-row table. `20260923_0900` and `20260923_1000` then applied cleanly, creating `scheduler_job_state`, `scheduler_worker_state`, and `prediction_market_archive`.
- **Durable scheduler outcomes observed in production (P0-B exit gate).** `scheduler_job_state` held 19 rows and `scheduler_worker_state` showed a live heartbeat (`running=true`, `missed_runs=0`). Recorded outcomes included `ok`, `skipped`, and `timeout` — including a real `timeout` on *Prediction Market Intraday Snapshot*. Previously these were process-local and the API would have reported an empty healthy list.
- **Unavailable-versus-value contracts observed against the live API.** `GET /equity/ZZZZZINVALID/quote` returned `data: null` with an explicit error instead of a fabricated zero price; a valid `VNM` quote returned a real price with a trade date. `GET /market/heatmap` returned `price_updated_at: 2026-07-01` separately from `constituents_as_of: 2026-09-24` with `constituents_stale: true` and `partial: true`. `GET /screener/` returned structured `meta` (`source`, `cached`, `stale`, `fallback`, `visible_field_coverage`).
- **Fixture provenance confirmed (closes the fail-open shape).** After an external provider failure the scheduler logged `using offline seed`; the rows it produced were stored with `is_synthetic=true` (`predictit` 20, `limitless` 10, `manifold` 10) while live rows stayed `false` (`kalshi` 14,553,619, `polymarket` 130).
- **Frontend verified against the new backend.** `https://vnibb-web.vercel.app/dashboard` loaded and issued its API traffic to `https://129.150.58.64.sslip.io/api/v1/*`; the dashboard rendered live index values and a truthful `DATA VALIDATION DEGRADED` banner driven by `/market/freshness` (foreign trading `critical`, `latest_sync_unsettled`, raw `2026-09-22` vs settled `2026-07-02`).
- **Stability window green.** `/health/` returned 200 on 15 consecutive minute samples with no unhealthy containers and zero 5xx responses in the API log over the 20 minutes following the recreate. CORS preflight for `https://vnibb-web.vercel.app` returned 200.
- **Still unproven (do not close on this alone):** independent encryption-key custody/decryption on a separate machine, production-scale prediction-query latency/peak-memory measurements, a host-loss restore from the current set, and the retention utility's `--apply` path against the serving database (which remains dry-run by default and operator-gated).
- **Operator note:** the `vnibb` database's tables were owned by `supabase_admin` while the migrate role is `postgres`, so any `ALTER TABLE` on an existing table failed. Ownership of 35 tables and 33 sequences was reassigned to `postgres`. Provision fresh databases with the app role as owner.
